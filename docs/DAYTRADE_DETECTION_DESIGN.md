# 단타 종목 탐지 로직과 지속 검증

## 목적과 한계

단타 후보는 자동 매매나 수익 보장이 아니라, 실제 저장 데이터에서 다음 거래일 단기 움직임을 검증할 수 있는 후보로 정의한다. “수익 최대화”는 한 번의 백테스트에서 가장 높은 수익률을 고르는 뜻이 아니라, 거래비용·슬리피지·기간 분할을 포함해 재현성이 확인된 조건을 선택하는 뜻으로 관리한다.

## 현재 신호 계약

`lib/daytrade-signal.ts`의 `evaluateDayTradeSignal`은 완료된 일봉만 입력으로 받는다. 최소 35봉이 필요하며 다음 조건을 모두 통과해야 `QUALIFIED`다.

- 종가 > EMA(9) > EMA(20)
- 최신 봉이 양봉
- 최신 거래량 / 직전 20봉 평균 거래량(RVOL) ≥ 1.0
- 최근 3봉 OBV 기울기 상승
- 최근 3봉 ADL 기울기 상승

OBV는 종가 방향에 따른 거래량 누적을 사용하고, ADL은 각 봉의 고가·저가·종가로 계산한 표준 Money Flow Multiplier와 거래량을 누적한다. 고가와 저가가 같은 봉의 ADL 기여도는 0으로 처리한다. `marketCap`, `tradingValue`, `minTurnoverRatio`를 함께 명시한 호출에서는 거래대금/시가총액 비율도 실제 통과 게이트로 적용하며, 기준 미달 후보는 `TURNOVER_BELOW_THRESHOLD`로 탈락시킨다.

조건 일부만 만족하면 `WATCH`, 이력이 부족하면 `INSUFFICIENT_HISTORY`, 그 외는 `REJECTED`다. 진입 가격은 신호 종가가 아니라 다음 거래일 시가를 기준으로 검증해야 한다. 신호 결과에는 기준일, EMA, RVOL, OBV·ADL 변화, 근거와 탈락 사유를 함께 보존한다.

`recommendMultiTimeframe(market, "scalp")`는 이 순수 신호 평가기를 실제 후보 추출 경로에서 호출한다. 따라서 기존 점수만 높은 종목이 단타 결과에 섞이지 않고, 일봉 조건을 모두 충족한 `QUALIFIED` 종목만 반환된다. 응답에는 `dayTrade`와 일·주·월봉 갱신 메타데이터가 함께 포함된다. `swing`과 `all` 모드는 기존 다중 시간봉 점수 계약을 유지한다.

운영 호출은 전용 `GET /api/scan/daytrade?market=KR|US&limit=30` 라우트를 사용한다. `market`은 국내(`KR`) 또는 해외(`US`, 기본값)로 고정하고 `limit`은 1~100으로 제한한다. 내부 오류는 HTML 오류 페이지가 아닌 `{ ok: false, error: "DAYTRADE_SCAN_UNAVAILABLE" }` JSON과 HTTP 503으로 반환하여 UI와 디버깅 API가 동일한 계약을 사용한다. 이 라우트는 기존 `scalp` 판정기를 재사용하므로 신호 기준이 분기되지 않는다.

## 실제 DB 검증

`scripts/backtest-daytrade.mjs`는 `.env.local`의 `DATABASE_URL`로 국내 또는 해외 보통주·활성·일봉 캐시를 읽는다. 기본 최근 180일을 시간순으로 재생하며, 다음 조합을 비교한다.

- RVOL: 0.7, 1.0, 1.2, 1.5
- 목표: 0.5%, 1%, 2%, 3%, 5%
- 손절: 0.5%, 1%, 2%, 3%
- 최대 보유: 1일, 3일, 5일
- 기본 비용: 왕복 20bp (`DAYTRADE_FEE_BPS`로 변경)
- 종목별 재진입 쿨다운: 기본 0일, `DAYTRADE_COOLDOWN_DAYS`로 지정

신호가 확정된 다음 거래일 시가에 진입하며, 비용을 반영한 진입가를 사용한다. 목표와 손절이 같은 봉에 도달하면 보수적으로 손절을 먼저 처리한다. 결과는 신호 수, 승률, 평균 수익률, 누적 단순수익률을 출력하며 표본 30건 미만 조합은 제외한다. 이는 “최고 조합”을 확정하는 도구가 아니라 과최적화 후보를 발견하는 도구다.

쿨다운이 양수이면 같은 종목에서 직전 채택 신호 이후 지정 일수 동안 중복 진입을 제외한다. 이를 통해 신호가 겹치는 낙관적 백테스트와 단일 포지션 운용에 가까운 결과를 분리한다. 쿨다운 결과가 좋아져도 표본 감소와 기간 분할 검증을 함께 통과해야 하며 운영 기준은 자동 변경하지 않는다.

`scripts/backtest-daytrade.mjs`에는 `DAYTRADE_MIN_TURNOVER_RATIO` 선택형 연구 게이트도 있다. 일봉 거래대금은 해당 봉의 종가×거래량으로 근사하고, 시가총액은 최신 저장 fundamental snapshot을 사용하므로 이 결과는 참고용이며 운영 신호에 자동 적용하지 않는다. 2026-09-21 국내 최근 180일에서 `0.01`(시총 대비 1%) 게이트를 적용한 최선 평균은 `-0.5768%`(2,237건), 게이트를 적용하지 않은 최신 기준 최선은 `-0.4944%`였고, `0.001` 게이트도 `-0.4985%`였다. 현재 데이터에서는 거래대금/시총 하한이 기대값을 개선하지 못했다.

2026-09-21 실제 DB에서 `DAYTRADE_COOLDOWN_DAYS=3`도 비교했다. 최근 180일 최선 조합은 국내 평균 `-0.4992%`(2,946건)로 여전히 음수였다. 쿨다운은 신호 수와 총 누적 손실을 줄였지만 평균 기대값을 양수로 바꾸지 못했으므로 운영 기본값으로 채택하지 않았다. 이 결과는 현재 실행 환경에서 재실행한 결과를 우선하며, 해외 결과는 동일 기준으로 재수집한 뒤 별도로 기록한다.

출구 범위가 좁아 생긴 편향을 확인하기 위해 목표 `0.5%·1%·2%·3%·5%`, 손절 `0.5%·1%·2%·3%`, 보유 `1·3·5` 거래일로 확장해 240개 조합을 재탐색했다. 운영 코드와 동일하게 전체 이력 EMA를 사용한 최신 국내 결과의 최선은 `RVOL ≥ 1.5`, 목표 5%, 손절 0.5%, 1일 보유의 평균 `-0.3450%`(4,064건)였지만 여전히 음수이고, 동일 기간 선택 결과이므로 운영 기본값으로 승격하지 않았다. 승률이 높은 조합도 손실이 커지는 것을 확인해 승률만으로 선택하지 않는다.
해외도 동일한 240개 조합을 실행했으며, 최근 180일 최선은 `RVOL ≥ 1.5`, 목표 5%, 손절 0.5%, 5일 보유의 평균 `-0.1931%`(11,661건)였다. 손실 폭은 작지만 양수 전환이나 기간 분할 검증이 아니므로 운영 기본값으로 승격하지 않는다.

확장된 300개 조합을 360일 시간순 walk-forward(학습 60%·검증 40%)로 재검증했다. 운영 코드와 동일한 전체 이력 EMA 기준으로 국내 학습 최선(`RVOL ≥ 2`, 목표 5%, 손절 0.5%, 3일)은 검증 평균 `-0.3925%`(2,095건), 해외 동일 학습 최선은 검증 평균 `-0.2587%`(7,274건)였다. 학습 구간에서 고른 조건도 검증 구간에서 음수였으므로 출구 조합을 운영 기본값으로 승격하지 않는다.

이번 재검증에서 연구 스크립트의 EMA 계산이 최근 60봉으로 잘려 운영 신호의 전체 이력 EMA와 달랐던 문제를 발견했다. `scripts/backtest-daytrade.mjs`와 `scripts/walkforward-daytrade.mjs`를 전체 이력 EMA로 통일하고, 통일 후 결과만 성능 판단의 근거로 인정한다.

`scripts/research-daytrade-candle-quality.mjs`로 다음 거래일 시가 진입 시 봉의 종가 위치와 EMA(9) 이격 필터도 연구했다. 전체 이력 EMA로 재실행한 검증 결과, 국내 최선(`종가 위치 ≥ 0.6`, EMA 이격 ≤ 3%) 평균 `-0.4601%`, 해외 최선(`종가 위치 ≥ 0.75`, EMA 이격 ≤ 3%) 평균 `-0.3734%`로 여전히 음수였다. 기본 조건보다 손실은 줄었지만 양수로 전환되지 않았으므로 운영 신호에는 추가하지 않는다.

## 지속 개선 루프

1. 최신 DB 캐시로 동일 스크립트를 실행한다.
2. 과거 60%를 탐색, 최근 40%를 검증 구간으로 분리한다.
3. 검증 구간에서도 누적수익·평균수익·최대손실·표본 수가 유지되는 조건만 다음 후보로 승격한다.
4. 시장별·거래일별·종목별 중복 신호를 분리해 한 종목의 반복 신호가 결과를 과대평가하지 않게 한다.
5. 운영 후보에는 `logicVersion`, `dataAsOf`, `signalDate`, `entryReference`, `costAssumption`, `reasons`를 포함한다.

단타 운영 탐지는 분봉을 사용하지 않고 최신 완료 일봉만 사용한다. 실제 분봉은 현재 일봉 신호의 판정·추출·알림 경로에 연결하지 않는다. 향후 별도 장중 전략을 검토할 때만 분봉 진입·청산 검증을 독립 연구로 수행하며, 일봉 기반 결과와 섞지 않는다.

`scripts/report-daytrade-data-quality.mjs`는 일봉·1분봉의 행 수, 종목 수, 거래일 범위와 검증 가능 여부를 출력한다. 장중 검증은 시장별 최소 20거래일의 1분봉이 있어야 `usableForIntradayValidation=true`로 판정하며, 이 기준을 충족하지 못하면 수익성 조합을 운영 기본값으로 승격하지 않는다. 2026-09-21 현재 로컬 DB의 1분봉은 국내 3거래일(`20260824~20260826`), 해외 1거래일(`20260825`)이라 두 시장 모두 승격 불가다.

독립 실행 연구 스크립트는 `scripts/load-local-env.mjs`를 먼저 불러 `.env.local`의 `DATABASE_URL`을 주입한다. 이전에는 `node scripts/report-daytrade-data-quality.mjs`처럼 직접 실행하면 셸 환경에 `DATABASE_URL`이 없을 때 인증 오류가 발생해 데이터 품질 확인 자체가 중단될 수 있었다. 스크립트는 환경변수 원문을 출력하지 않으며, 셸에서 명시한 값은 보존한다.

2026-09-21 최신 DB 재실행: 국내 일봉은 2,455종목·279,564행·128거래일(`20260317~20260918`), 해외 일봉은 5,375종목·5,051,209행·1,597거래일(`20200511~20260917`)이었다. 국내 최근 180일 240개 조합의 최선은 `RVOL ≥ 1.5`, 목표 5%, 손절 0.5%, 1일 보유로 평균 `-0.34497%`, 누적 `-14.02`, 4,064건이었다. 승률 최상위 조합도 평균 `-1.36366%`로 음수였다. 최신 데이터에서도 비용 후 양수 기대값은 확인되지 않았으므로 운영 기본값은 변경하지 않는다.

같은 최신 DB에서 국내 360일 walk-forward도 재실행했다. 비교 가능 종목은 2,344개였고, 학습 최선(`RVOL ≥ 2`, 목표 5%, 손절 0.5%, 3일)의 검증 평균은 `-0.39251%`, 누적 `-8.2230`이었다. 모든 상위 검증 조합이 `promotable=false`였으므로 운영 조건은 변경하지 않는다.

## 2026-09-21 실제 DB 검증 결과

로컬 `.env.local` DB에서 국내 활성 보통주 2,347개, 일봉 269,954봉, 최근 180일을 대상으로 다음 거래일 시가 진입으로 실행했다. 왕복 비용 20bp를 반영한 48개 조합 모두 평균수익률과 누적 단순수익률이 음수였다. 가장 덜 나쁜 조합도 `RVOL ≥ 1.5`, 목표 2%, 손절 0.5%, 최대 1일 보유로 평균 `-0.5409%`, 누적 `-28.49`였다. 승률만 가장 높은 조합(`RVOL ≥ 0.7`, 목표 0.5%, 손절 1%, 3일)은 승률 15.28%와 평균 `-0.9698%`로 실전 후보가 될 수 없다.

따라서 현재 신호를 수익 극대화 로직으로 확정하거나 자동 알림·매매에 연결하지 않는다. 다음 개선은 신호 중복 제거, 시장 국면 분리, 다음날 시가 갭·유동성 필터, 분봉의 실제 진입·청산 가격을 포함한 시간순 walk-forward 검증이다. 검증 구간에서도 비용 차감 후 양의 평균수익과 충분한 표본이 확인될 때만 운영 기본값 후보로 승격한다.

## 운영 안전 기준

- 비활성·ETF·워런트·파생·거래정지 종목은 신호 계산 전에 제외한다.
- 결측·0 거래량·잘못된 OHLC는 신호와 백테스트에서 제외한다.
- 최신 캐시 기준일과 갱신시각을 결과에 표시한다.
- `QUALIFIED`는 알림 후보이지 매수 명령이 아니다.
- 수익률이 가장 높은 단일 조합을 운영 기본값으로 자동 변경하지 않는다. 기간 분할 검증과 비용 반영을 통과해야 수동 승인한다.

## 시가총액 시점성 제한

`instrument_fundamental_snapshots`는 현재 종목별 최신 스냅샷 1건을 보관하는 구조(`UNIQUE (market, code)`)다. 따라서 과거 거래일의 실제 시가총액을 복원할 수 없으며, 과거 백테스트에서 현재 시총을 과거 시점의 게이트로 사용하면 미래 정보 누수와 표본 편향이 생길 수 있다. `DAYTRADE_MIN_TURNOVER_RATIO`는 이 제한을 명시한 연구용 참고 게이트로만 유지하고 운영 신호에 자동 적용하지 않는다. 시총 대비 거래대금 조건을 수익성 검증에 승격하려면 관측일시별 시총 이력 테이블과 거래일 기준 `observed_at <= signal_date` 조회를 먼저 도입해야 한다.

이를 해결하기 위해 V134 `instrument_fundamental_history`를 추가하고, 재무 스냅샷 갱신 시 최신 테이블과 함께 관측 시점별 이력을 저장하도록 개발했다. 향후 백테스트는 신호일 이전의 가장 최근 이력만 조회해야 하며, 이 마이그레이션이 운영 DB에 적용되고 충분한 과거 이력이 쌓이기 전까지 기존 결과는 참고용으로만 취급한다.

적용 여부는 `node scripts/report-fundamental-history.mjs`로 확인한다. `readyForAsOfMarketCapValidation=true`가 되기 전에는 시총 게이트 연구 결과를 운영 승격 근거로 사용하지 않는다.

로컬 PostgreSQL이 실행 중이고 Docker API만 사용할 수 없는 경우에는 `node scripts/apply-local-v134.mjs`로 V134를 적용할 수 있다. 이 스크립트는 연결 호스트가 `localhost`, `127.0.0.1`, `::1`인 경우에만 실행하며 원격·운영 DB에는 적용하지 않는다.

`scripts/backtest-daytrade.mjs`의 시총 게이트 경로도 미래 누수를 차단하도록 변경했다. `DAYTRADE_MIN_TURNOVER_RATIO > 0`일 때만 `instrument_fundamental_history`에서 각 신호일 다음날 00시 이전의 최신 시총을 조회하며, 이력이 없는 봉은 게이트를 통과하지 않는다. 게이트를 사용하지 않는 기본 연구는 시총을 조회하지 않아 V134 미적용 환경에서도 기존 일봉-only 성과 검증이 가능하다.

## 구조별 연구 결과

`scripts/research-daytrade-variants.mjs`는 추세 추격(`trend`), EMA(9) 재탈환 눌림(`ema9-reclaim`), EMA(20) 부근 반전(`ema20-reversal`)을 같은 DB·다음 거래일 시가·왕복 비용 20bp 조건으로 비교한다. 비용 모델 수정 후 2026-09-21 국내 2,347개 종목·최근 360일 결과에서 가장 덜 손실인 구조는 `ema20-reversal`, 목표 1%, 손절 0.5%, 1일 보유의 평균 `-0.5341%`였다. 세 구조와 모든 목표·손절·보유 조합이 음수였으므로 새 구조도 운영 신호로 승격하지 않았다.

`scripts/research-daytrade-entry-gap.mjs`는 다음 거래일 시가가 신호 종가 대비 어느 범위의 갭으로 시작할 때 성과가 달라지는지 검증한다. 비용 모델 수정 후 2026-09-21 국내 2,347개 종목·최근 360일·왕복 20bp 결과에서 갭 필터 중 최선은 필터 없음(`target 1%`, `stop 0.5%`)의 평균 `-0.5535%`였다. 갭 필터도 양수 개선 근거가 없어 운영 조건에 추가하지 않았다.

`scripts/walkforward-daytrade.mjs`는 각 종목의 비교 가능한 일봉 길이를 기준으로 앞 60%에서 조건 조합을 선택하고 뒤 40%에서 동일 조합을 재평가한다. 검증 구간의 평균수익률이 음수이거나 표본이 부족하면 운영 후보로 승격하지 않는다.

재발 방지를 위해 walk-forward 출력에 승격 판정을 명시했다. 검증 신호가 100건 이상이고 거래비용 차감 후 평균수익률과 누적수익률이 모두 양수일 때만 `promotable=true`가 되며, 그렇지 않으면 `INSUFFICIENT_VALIDATION_SAMPLE` 또는 `VALIDATION_NET_NEGATIVE_AFTER_COST` 사유를 남긴다. 이 값은 운영 조건을 자동 변경하지 않고 수동 검토의 명시적 게이트로 사용한다.

2026-09-21 재점검에서 운영 신호만 표준 ADL이고 백테스트·walk-forward·갭 연구 스크립트는 구식 종가 방향 ADL을 사용하던 불일치를 발견했다. `scripts/backtest-daytrade.mjs`, `scripts/walkforward-daytrade.mjs`, `scripts/research-daytrade-entry-gap.mjs`를 운영 신호와 동일한 Money Flow Multiplier 기반 ADL로 통일했다. 이후 산출 결과만 다음 운영 승격 판단의 근거로 인정한다.

2026-09-21 실행 결과: 국내 2,347개 종목(비교 가능 2,344개), 최근 360일, 다음 거래일 시가 진입, 왕복 20bp 기준으로 학습 구간 최상위도 `RVOL ≥ 2`, 목표 5%, 손절 0.5%, 3일 보유에서 평균 `-0.4487%`였고 전체 이력 EMA 기준 검증 구간은 평균 `-0.3925%`, 누적 `-8.22`였다. 시간순 검증에서도 양수로 유지되는 조합이 없어 운영 기본값으로 승격하지 않았다.

ADL 계산 통일 후 재실행한 최신 결과는 이전 수치보다 우선한다. 최근 180일 백테스트에서 국내는 2,347개 종목·269,954행 기준 최선 조합(`RVOL ≥ 1.5`, 목표 2%, 손절 0.5%, 1일)의 평균 `-0.5427%`, 해외는 5,306개 종목·633,427행 기준 최선 조합(`RVOL ≥ 1.5`, 목표 2%, 손절 0.5%, 3일)의 평균 `-0.4631%`였다. 48개 조합 모두 음수였다. 360일 walk-forward에서도 국내 검증 최선 조합은 평균 `-0.5344%`, 해외는 `-0.4924%`로 음수였으므로 어느 시장도 운영 수익 전략으로 승격하지 않았다. 표준 ADL 통일은 검증의 일관성을 개선했지만 수익성을 입증하지는 못했다.

이후 비용 모델 점검에서 진입가에 수수료를 더한 뒤 왕복 비용을 다시 차감하던 중복 반영을 발견해 수정했다. 최신 비용 모델은 진입가는 원시 시가로 두고 결과 수익률에서 왕복 20bp를 한 번만 차감한다. 수정 후 2026-09-21 재실행한 최근 180일 최선 조합은 국내 평균 `-0.4944%`, 해외 평균 `-0.3718%`였고, 48개 조합 모두 음수였다. 수정된 360일 walk-forward 검증도 국내 `-0.5258%`, 해외 `-0.4256%`로 음수였다. 이 수치를 이전 비용 모델 결과보다 우선한다.

운영 다중시간봉 추천의 흐름 점수도 `calculateDayTradeFlowState`에서 동일한 표준 ADL을 사용한다. 이 계산은 백테스트와 후보 API 사이의 지표 정의가 갈라지지 않도록 회귀 테스트로 고정한다.

2026-09-21에는 같은 거래일에 여러 후보가 발생할 때 상대적으로 강한 후보만 선택하는 교차 종목 랭킹을 연구했다. `scripts/research-daytrade-daily-ranking.mjs`는 표준 ADL·OBV·RVOL·봉 종가 위치·EMA(9) 이격을 결합한 점수로 신호를 정렬하고, 거래일별 상위 1·3·5·10개와 전체 신호를 다음 거래일 시가에 비교한다. 왕복 비용 20bp, 목표 2%, 손절 0.5%를 적용했다.

- 국내: 81거래일, 상위 1개 81건 평균 `-0.5765%`, 상위 5개 405건 `-0.5642%`, 전체 7,000건 `-0.4704%`
- 해외: 209거래일, 상위 1개 209건 평균 `-0.2747%`, 상위 3개 627건 `-0.3290%`, 전체 67,549건 `-0.3135%`

상대 랭킹은 해외 상위 1개에서 손실을 일부 줄였지만 비용 차감 후 양수로 전환하지 못했고, 국내에서는 전체 신호보다 개선되지 않았다. 따라서 거래일별 상위 N 선택을 운영 기본값이나 알림 기준으로 승격하지 않는다. 향후에는 시장 국면·유동성·장중 분봉 데이터가 충분히 확보된 뒤 학습/검증 기간을 분리한 교차 종목 랭킹을 다시 검증한다.

이번 교차 종목 재검증에서도 연구 스크립트의 EMA를 운영 신호와 동일한 전체 이력 계산으로 통일했다. 결과는 이전 60봉 EMA 결과보다 우선하며, 상위 후보 선택만으로 비용 후 양수 기대값은 확인되지 않았다.

추가로 `scripts/research-daytrade-regime.mjs`에서 종목별 신호일의 시장 breadth를 계산했다. `종가가 상승 중인 EMA(20) 위`인 종목 비율이 55% 이상이면 BULL, 35% 이하이면 BEAR, 나머지는 NEUTRAL로 분류하고 다음 거래일 시가 진입·왕복 20bp·목표 2%·손절 0.5%로 평가했다. 전체 이력 EMA로 재실행한 360일 실제 DB 결과는 국내 BULL `-0.4597%`(1,768건), NEUTRAL `-0.4693%`(2,929건), BEAR `-0.4800%`(2,303건), 해외 BEAR `-0.2877%`(9,546건), NEUTRAL `-0.3173%`(50,134건), BULL `-0.3204%`(7,869건)였다. 국면별 차이는 관찰되지만 어느 국면도 비용 후 양수가 아니므로 특정 국면만 허용하는 운영 게이트로 승격하지 않는다. 후속 검증에서는 학습·검증 구간을 분리하고 breadth 임계값을 고정하지 않은 상태에서 최적화하지 않도록 별도 검증한다.

롱 전용 편향을 점검하기 위해 `scripts/research-daytrade-short.mjs`로 동일한 추세·RVOL·OBV·표준 ADL 조건의 반대 방향 신호도 연구했다. 공매도 가능 여부와 차입비용은 반영하지 않은 참고용 상한이며, 다음 거래일 시가·목표 2%·손절 0.5%·왕복 20bp만 적용했다. 전체 이력 EMA로 재실행한 국내 11,039건의 평균은 `-0.2924%`, 해외 64,280건은 `-0.3392%`로 모두 음수였다. 따라서 현재 데이터와 비용 가정에서는 롱/숏 어느 방향도 운영 수익 전략으로 승격하지 않는다. 실제 숏 전략을 고려하려면 대차 가능 종목, 차입료, 공매도 제한, 강제상환 및 장중 체결 데이터를 추가해야 한다.
실제 숏 전략을 고려하려면 대차 가능 종목, 차입료, 공매도 제한, 강제상환 및 장중 체결 데이터를 추가해야 한다.

ATR 기반 손절·목표 조합을 사전 검토하는 과정에서 신호와 ATR을 조합별 반복 계산하는 프로토타입이 실제 DB 규모에서 과도한 실행시간을 보였다. 해당 프로토타입은 제거했고 결과를 성과 근거로 사용하지 않는다. 재시도 시에는 종목별 신호·ATR·미래 봉 경로를 1회 사전 계산한 뒤 조합만 평가해 계산량을 선형화하고, 실행시간 상한과 중간 진행 지표를 추가한다.

2026-09-21 운영 추출 기준을 명확히 분리했다. `recommendMultiTimeframe(..., "scalp")`와 `GET /api/scan/daytrade`는 이제 해당 시장 DB에서 가장 최신인 완료 일봉 날짜(`latestDailyDate`)와 정확히 일치하는 종목만 후보로 반환한다. 과거 날짜에 멈춘 종목은 조건을 만족해도 다음 거래일 후보에서 제외하며, 응답에 `signalBasis: "latest completed daily candle only; next session open required"`를 포함한다. 따라서 과거 백테스트용 신호와 다음 거래일 실전 관찰용 후보가 섞이지 않는다. 이 기준을 회귀 테스트로 고정했다.

완료 봉 경계도 SQL에서 고정했다. 단타 경로는 국내 `Asia/Seoul`, 해외 `America/New_York` 현지 날짜의 당일 일봉을 제외하므로 장중 미완성 봉이 신호에 섞이지 않는다. 백테스트도 동일하게 오늘 봉을 제외해 운영 판정과 연구 판정의 봉 경계를 일치시킨다.

같은 경로의 조회 성능도 개선했다. 단타 지표와 기술 분석에 필요한 최근 140개 일봉, 30개 주봉·월봉만 `ROW_NUMBER()`로 제한해 가져오도록 변경했다. 로컬 실제 API 검증에서 해외 요청은 기존 약 55.9초에서 약 18.0초로 줄었고, HTTP 200·후보 5건·`latestDailyDate=20260917`·다음 세션 기준 메타데이터를 확인했다. 이 측정은 개발 DB 기준이며 운영 성능은 DB 인덱스·동시 요청에 따라 재측정한다.

2026-09-21 로컬 실행 검증에서도 `GET /api/scan/daytrade?market=KR&limit=5`가 HTTP 200과 후보 5건을 반환했고, `latestDailyDate=20260918`, 모든 확인 후보의 `signalDate=20260918`, `signalBasis=latest completed daily candle only; next session open required`를 확인했다. 실제 응답 기준일과 운영 신호일이 일치하므로 완료 봉 필터가 실행 경로에도 반영된 상태다.

추가로 `mode="scalp"`에서는 주봉·월봉을 아예 조회하지 않고 최근 140개 일봉만 읽도록 분리했다. 실제 로컬 API 재측정에서 해외 응답은 약 13.5초, HTTP 200, 후보 5건, `latestDailyDate=20260917`을 확인했고, 단타 결과의 주·월봉 메타데이터는 `null`로 명시된다. 주·월봉을 포함한 분석은 `swing`/`all` 모드의 책임으로 유지한다.

2026-09-21 로컬 DB 직접 확인 결과 최신 일봉은 국내 `20260918`(2,351종목·2,351행), 해외 `20260917`(5,306종목·5,306행)으로 확인됐다. 운영 단타 API는 이 시장별 최신 일봉 날짜와 일치하는 종목만 반환하므로, 시장 휴장일 차이를 하나의 전역 기준일로 잘못 처리하지 않는다.
