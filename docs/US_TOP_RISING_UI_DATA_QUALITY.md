# 미국 상승률 TOP100 UI 데이터 품질 및 누락 방지

상태: 구현 기준
최종 확인: 2026-10-07

## 데이터 경로

```text
KIS 해외주식 상승률 순위
  └─ NAS / AMS / NYS 거래소별 최대 100행
       ↓ 성공 응답 검증 + 부족 행은 VOL_RANG=0 재조회
상품 유형 규칙 → 활성 COMMON_STOCK 공식 마스터 대조(fail-closed)
  → 선택적 시총 필터 → 점수 후보 우선 + 거래소 round-robin 순위로 분봉 관측 풀 보충
  → 프로세스 메모리 snapshot → /api/stock/us/top-rising-chart → /us-top-rising UI
  → 최대 30개 후보의 KIS 1분봉 조회 → 최근 1~10분 거래대금 메모리 집계 → /intraday UI
```

TOP100은 **각 거래소별 원천 순위 최대 100행**을 뜻한다. ETF·워런트 등 상품 유형과 공식 종목 마스터의 활성 보통주 조건을 적용한 뒤 UI에 노출하므로, 최종 종목 수가 거래소마다 100개보다 적은 것은 정상일 수 있다. 화면의 카드 순위는 각 거래소 원천 rank이며, 전체 보기는 NAS → AMS → NYS 거래소 순서 안에서 rank 오름차순으로 표시한다. 집중 탐지 후보 영역은 원천 랭킹이 아니라 우선순위 점수 순서다.

## 정확성 계약

- 순위 응답은 HTTP 2xx, `rt_cd=0`일 때만 성공 데이터로 인정한다. 실패 payload에 행 배열이 함께 있더라도 후보로 쓰지 않는다.
- 원천 순위 행이 100개보다 적으면 `VOL_RANG=0` fallback을 시도한다. fallback 실패 시 이미 성공한 기본 응답 행을 유지하며 거래소별 부분 상태를 표시한다. 한 거래소의 예외가 다른 거래소의 정상 결과를 버리지 않는다.
- 거래소별 `sourceCount`, `sourceComplete`, 상품 규칙 통과 수, 최종 활성 보통주 수, 제외 수, 오류 사유, 원천 수집 시각을 API와 UI에서 분리한다.
- 거래소별 원천 행 감산은 상품 제외, 티커 누락, 중복 제거, 필터 통과 유효 행으로 분리해 UI에 표시한다. 차트 종목 선택은 목록 인덱스가 아닌 `market:code` 키로 고정하여 자동 순위 갱신 중 다른 티커로 바뀌지 않게 한다.
- KIS 숫자 필드가 null/undefined/빈 문자열이면 0으로 바꾸지 않고 `null`로 유지한다. 실제 0 값은 0으로 보존하며, provider rank가 있으면 UI 순위에 사용하고 없을 때만 원천 행 위치로 대체한다.
- 전체 `complete=true`는 세 거래소가 모두 성공 응답을 반환하고 각각 100행을 채운 경우에만 허용한다. 정상 응답이어도 1~99행이면 부분 수신이다.
- `collectedAt`은 API가 만들어진 시각이 아니라 KIS 응답을 실제 받은 시각이다. UI에는 초 단위 수집 시각과 경과 초를 표시하고, 60초 초과 시 stale 경고를 낸다.
- KIS의 성공된 원천 결과를 프로세스 메모리에서 재사용한다. 브라우저는 15초마다 API를 재조회하지만, 이것이 KIS 호출을 직접 발생시키지는 않는다. 장중 원천 갱신은 기존 worker 및 30초 universe cache가 소유한다.
- KIS 상승률 응답에 시총/거래대금 값이 있어 점수를 계산할 수 있는 후보를 먼저 관측 큐에 배치하고, 남은 슬롯은 이미 활성 보통주 및 설정 필터를 통과한 후보 중 거래소별 원천 순위 round-robin으로 채운다. 최대 30개로 제한한다. 응답 필드 누락이 분봉 큐 전체를 0개로 만들거나 NAS 한 거래소가 슬롯을 독점하는 일을 막는다.
- 실제 분봉 조회는 KIS 해외주식 `inquire-time-itemchartprice`의 1분봉(`NMIN=1`)을 사용한다. 최근 1~10분 합계는 메모리의 분 단위 관측으로 계산하며, 같은 1분봉을 반복해서 더하지 않는다. 응답이 비거나 지연되면 완전한 윈도우로 가장하지 않고 샘플 수/품질 상태로 표시한다.
- 시총이나 거래대금 순위 입력이 누락된 경우에도 분봉 금액 자체는 관측할 수 있지만 시총 대비 비율 및 비율 기반 알림은 계산하지 않는다. 누락값은 0으로 대체하지 않는다.
- 집중 탐지 후보 UI는 최대 30개 실제 분봉 큐 항목을 보여주며, `/intraday`의 미국 집중 관측 표는 관측된 분봉의 최근 1~10분 금액과 시총 대비 비율(시총 확인 시에만)을 제공한다.
- 원천 수집 시각이 누락된 메모리 fallback 결과는 최신성 미확인 경고를 표시한다. 시각이 확인되는 경우에도 60초 초과는 stale로 표시한다.
- KIS 원문 응답 preview 및 비밀값은 사용자 API DTO에 포함하지 않는다.

## 남은 경계와 운영 리스크

- KIS가 정상 `rt_cd=0`과 부분 행을 반환하고 fallback도 부족하면 원천 누락을 복구할 수 없다. 이 경우 완전 수신으로 표시하지 않고 거래소별 누락 행 수와 상태를 보인다.
- 활성 보통주 마스터 확인 실패 시 fail-closed라 후보가 줄거나 0개가 될 수 있다. 이는 상품 오탐을 막는 의도된 동작이며 API `criteria.officialEligibility`의 `lookupFailed`와 관리자 진단으로 확인한다.
- 거래소 통합 우선순위 상위 최대 30개만 고빈도 집중 관측 대상이다. TOP100 카드 표시 범위와 분봉 관측 범위를 혼동하지 않는다.
- 프로세스 재시작 직후 메모리 snapshot이 비어 있으면 첫 API 요청에서 universe를 hydrate한다. 실제 장외·공급자 휴지 시간에는 KIS가 빈 응답을 줄 수 있으므로, 이전 세션 데이터는 원천 시각과 stale 여부 없이는 최신이라고 표시하지 않는다.
- 로컬 개발 모드는 프로덕션 분봉 워커 자동 시작을 차단한다. 로컬 화면/API 확인만으로 워커 실행을 입증하지 않으며, 실제 KIS endpoint 실호출 또는 운영 워커 상태를 별도로 검증한다.

## 회귀 검증

- `lib/us-top-rising-universe.test.ts`: fallback 성공/실패 payload, primary 장애 후 fallback 복구, 100행 완전성 기준, 공식 보통주 fail-closed, 점수 불가 행이 있을 때 거래소 간 round-robin으로 분봉 슬롯을 보충하고 30개 상한 및 부족 거래소 슬롯 재분배를 지키는지 확인.
- `lib/kis-us-minute-turnover.test.ts`: 공식 해외 1분봉 query field set, 거래소 전달, 누적 거래량과 분당 거래량 구분.
- `app/api/stock/us/top-rising-chart/route.test.ts`: 실제 source timestamp, 부분 거래소 상태, 불필요한 raw payload 미노출, 캐시 재사용 시 DB snapshot 중복 저장 방지.
- `components/us-top-rising-chart-page.test.tsx`: 부분 수신·초 단위로 경과하는 KST 원천 시각 표시, 집중 후보 20개 초과 목록 및 실제 큐 순번 표시, 자동/수동 재조회 중 차트 종목 선택 유지, 시총 대비 비율 미확인 상태 설명.

## 변경 절차

KIS 응답 형식·rank 매핑·상품 필터·master 조회·snapshot DTO를 변경할 때 이 계약과 테스트를 함께 갱신한다. 배포 전에는 해당 테스트, 전체 typecheck, build, 로컬 실행 페이지 확인 및 `docs:check`를 수행하고 `DEVELOPMENT_LOG.md`에 결과와 남은 위험을 기록한다.
