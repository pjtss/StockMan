# 미국 OBV 다이버전스 즉석 계산 로컬 DB 벤치마크 (2026-10-30)

## 목적과 측정 범위

미국 OBV 다이버전스를 요청마다 즉석 계산할 때의 로컬 DB 조회·계산 시간을 가늠했다. `us-obv-divergence` 구현과 동일한 공식 활성 보통주 필터, 최신 160봉 조회 SQL, `evaluateUsObvDivergence` v4 함수를 사용했다. 운영 DB 및 운영 API에는 접근하지 않았다.

스크립트는 `.env.local`의 로컬 DB 연결만 허용하고 `BEGIN READ ONLY` 트랜잭션 안에서 SELECT했다. 마지막에 ROLLBACK했으며 쓰기 쿼리는 실행하지 않았다.

## 결과

| 단계 | 결과 |
|---|---:|
| 기준 최신 일봉 | 2026-10-27 |
| 공식 활성 미국 보통주 | 5,216종목 |
| 읽은 봉 | 810,666개 (종목당 최대 160개) |
| 최신일·유니버스 사전 조회 | 28.82초 |
| 종목별 최신 160봉 DB 조회 | 50.88초 |
| 행 정규화·종목별 그룹화 | 8.38초 |
| v4 다이버전스 계산·정렬 | 5.17~5.85초 (동일 메모리 데이터 3회) |
| 후보 JSON 직렬화 | 0.013초, 약 1.61MB |
| 측정 단계 합계 | 약 93.3초 |

전체 계산 중 SQL 준비/조회가 약 79.7초이고 순수 신호 계산은 약 5초였다. 즉석 계산 지연은 산술보다 DB 읽기와 결과 행 처리에 주로 좌우된다.

## 정석상 10봉 한계

현행 v4는 최소 80봉을 요구하고 최근 160봉까지 사용한다. TREND는 최근 20봉과 직전 기준 종가, PIVOT은 좌우 각 3봉으로 확정되는 저점 중 최근 두 저점을 비교하며 두 저점 간격이 최대 45봉이다. 따라서 최신 10봉만 읽으면 기존 알고리즘 신호를 재현할 수 없다. 10봉 버전은 별도 알고리즘·버전과 별도 검증이 필요한 다른 탐지기가 된다.

## 적용 시 해석

- 위 수치는 로컬 DB 및 현재 작업 호스트 측정치다. 운영 DB의 인덱스·CPU·부하·네트워크 왕복 차이가 있어 운영 응답시간 보장은 아니다.
- 로컬 DB의 최신 일봉은 2026-10-27이었다. 더 최근 데이터가 반영된 운영 기준 수치가 아니다.
- 현재 공개 GET `/api/scan/us-obv-divergence`는 스냅샷 행 하나를 읽고 결과를 필터링하는 구조다. 운영에서 인증 없이 호출은 가능하지만 2026-10-30 확인 시 `503 SNAPSHOT_NOT_READY`여서 현재 공개 경로의 성공 지연을 실측할 수 없었다.
- 공개 GET에서 매번 즉석 계산하도록 바꾸면 현재 로컬 구조 기준 약 1.5분까지 걸릴 수 있다. 운영값은 별도 staging/production 계측이 필요하다. 사전 계산 스냅샷 방식이 현재 응답 경로에 더 맞지만, 운영 성능 수치로 확정한 것은 아니다.
