# SEC EDGAR 공시 분석 기록 관리

## 목적

SEC 공시를 원문 filing 단위로 분석 문서화하고, 종목별 누적 이력과 날짜별 시장 요약을 일관되게 탐색한다. 공시 원문과 동일한 분석을 여러 인덱스에 복제하지 않는다.

## 저장 구조

```text
reports/sec-edgar-analysis/
├─ README.md                                      # 전체 인덱스와 분류 기준
├─ daily/YYYY-MM-DD.md                            # 날짜별 요약 및 그날의 filing 링크
└─ companies/{CIK}-{현재티커}/
   ├─ README.md                                    # 회사 누적 이력과 티커 alias
   └─ YYYY/MM/DD/{FORM}/{ACCESSION}.md             # filing 1건의 분석 원본
```

- `CIK`는 종목명 또는 티커 변경에도 유지되는 회사 식별자이므로 회사 폴더 키로 사용한다.
- 경로의 날짜는 일별 조회의 `Asia/Seoul` 기준일이다. Filing 본문의 event date, EDGAR 접수시각, KST 환산시각은 기록 본문에서 별도로 구분한다.
- `{FORM}`은 `8-K`, `8-K-A`, `10-Q`, `10-K`, `S-1`처럼 실제 제출 유형을 사용한다. `/`는 파일 경로에서 `-`로 바꾼다.
- `{ACCESSION}`은 SEC accession number를 그대로 사용한다. 같은 날 같은 Form이 여러 건이거나 정정 제출이 있어도 기록이 덮어쓰이지 않는다.
- 회사명이나 티커가 바뀌면 CIK 폴더를 새로 복제하지 않는다. 현재 티커와 과거 티커를 회사 README의 alias 표에 기록하고 일별 인덱스에는 해당 filing이 접수될 때 확인된 티커 및 현재 티커를 함께 적는다.
- Form 한 건에 여러 Item이 있으면 분석 문서 하나에 모든 해당 Item을 기록한다. Item별 별도 파일을 만들지 않는다.

## 분석 문서 필수 항목

각 accession 문서는 다음 내용을 갖는다.

1. CIK, 회사명, filing 당시 티커, 현재 티커, 시장, Form, Item, accession number
2. 일별 기준일(KST), SEC 접수시각(미 동부시간 및 KST), 회사가 보고한 사건일
3. SEC EDGAR 원문 링크
4. 운영서버 시총을 분석 범위에 사용했다면 USD 금액, snapshot 수집시각, 데이터 출처와 티커 alias 주의사항
5. 판정: `POSITIVE`, `NEGATIVE`, `MIXED`, `NEUTRAL`
6. 원문으로 확인된 사실과 회사의 전망·예정일을 분리한 핵심 요약
7. 긍정 근거, 하방·희석·상장·유동성·임상·규제 위험, 남은 확인 항목
8. 분석 한계. Form/Item 존재, 홍보자료, 예정 일정만으로 촉매의 실현이나 주가 방향을 단정하지 않는다.

## 판정 기준

| 판정 | 적용 기준 |
|---|---|
| `POSITIVE` | 확인된 사건이 사업·재무·규제 상태를 실질적으로 개선하며, 같은 filing의 중대한 상쇄 위험을 함께 검토한 경우 |
| `NEGATIVE` | 확인된 사건이 재무곤란, 희석, 상장·영업 위험 등 하방 요인을 실질적으로 드러낸 경우 |
| `MIXED` | 긍정 재료와 위험이 동시에 있거나, 임박한 표결·종결처럼 결과에 따라 방향이 달라지는 경우 |
| `NEUTRAL` | 자료 갱신·절차·예정 일정 위주로 당일 새로운 확정 촉매가 확인되지 않은 경우 |

분류는 공시 근거에 대한 정성 판단이다. 급등 여부, 상승확률, 목표가 또는 투자 권유를 뜻하지 않는다.

## 탐색 인덱스

- `README.md`: 기준·연도별 일별 문서와 종목별 회사 기록 링크
- `daily/YYYY-MM-DD.md`: 일별 조회 범위, 총량·필터, 호재/악재/혼재/중립 집계 및 accession별 기록 링크
- `companies/{CIK}-{현재티커}/README.md`: 회사 식별자·현재/과거 티커·시총 snapshot 주의·날짜순 filing 링크

모든 상세 판단과 SEC 원문 링크는 accession 기록을 기준으로 삼는다. 일별·종목별 인덱스는 요약과 링크만 유지한다.

## 신규 기록 추가 절차

1. 운영 일별 조회 API의 날짜를 명시하고 `sourceType`과 SEC 출처를 적용해 대상 범위를 고정한다.
2. API 목록만으로 결론 내리지 말고 각 대상 SEC filing의 실제 문서와 첨부 exhibit을 확인한다.
3. 시총 기준을 적용했다면 운영서버 snapshot을 이용하고 수집시각과 데이터 공백을 표시한다.
4. accession 단위 분석 문서를 추가한 다음 일별 문서와 해당 CIK 회사 인덱스에 링크를 등록한다.
5. UTF-8 한글·SEC 링크·대상 filing 수·인덱스 링크를 확인하고 `DEVELOPMENT_LOG.md`에 조회범위·결과·한계를 남긴다.

공식 출처는 SEC EDGAR filing 원문과 제출 상세 페이지다. 원문을 프로젝트에 복사하지 않고 SEC 링크와 분석에 필요한 요약만 보존한다.
