# 공지사항 분리 설계

## 요구사항

- 문의 게시판에는 공지글을 표시하지 않는다.
- 공지사항을 별도 페이지에서 제공한다.
- 네비게이션 바에 공지사항 메뉴를 추가한다.
- 문의 도메인과 공지 도메인을 분리한다.

## 설계

### 화면

| 경로 | 역할 | 데이터 조건 |
| --- | --- | --- |
| `/inquiries` | 문의 목록 | `is_notice = false` |
| `/notices` | 공지 목록 | `notices.is_published = true` |
| `/notices/[id]` | 공지 상세 | 공지 전용 상세 페이지 |

공지사항은 `notices` 전용 테이블과 전용 상세 페이지를 사용한다. 기존 문의의 공지 플래그 데이터는 최초 마이그레이션에서 이관하고, 이후 공지 lifecycle은 문의 도메인과 분리한다.

### 데이터/API

- `listInquiries()`는 일반 문의만 반환한다.
- `listNotices()`와 `getNotice()`는 `lib/notices.ts`에서 전용 테이블을 조회한다.
- 기존 `is_notice` 컬럼은 이관 호환성을 위해 남기며 신규 공지 기능에서는 사용하지 않는다.

### 네비게이션

`PageNavigation`에 `공지사항`을 추가하고 `/notices`로 연결한다. 기존 `문의` 메뉴는 `/inquiries`로 유지한다.

### 검증 기준

- 문의 목록에 공지글이 나타나지 않는다.
- 공지 목록에 일반 문의가 나타나지 않는다.
- 네비게이션에서 두 경로가 독립적으로 보인다.
- 문의 작성·댓글·좋아요 기능이 공지 기능과 독립적으로 유지된다.
- TypeScript 및 관련 테스트를 통과한다.
