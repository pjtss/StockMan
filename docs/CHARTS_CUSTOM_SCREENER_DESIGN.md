# `/charts` 사용자 직접 조건 추출 설계안

## 목표

`/charts`에서 고정된 preset 종목 추출 버튼은 노출하지 않고, 사용자가 시장·봉·지표·가격·거래량 조건을 직접 조합해 실행하는 단일 스크리너 흐름으로 통합한다.

## 현재 적용 범위

- preset 매집 추출 버튼을 UI에서 비활성화했다.
- 일반 `종목 추출` 버튼과 직접 조건 입력은 유지한다.
- 골든크로스, EMA9 위치, BB 위치, OBV·ADL 방향, RVOL, 시총, 가격 조건은 직접 설정형 필터로 취급한다.
- AND/OR 조건 결합, 기준일 지정, 조건 초기화, 시총·RVOL·거래대금·최신일·종목명 정렬을 제공한다.
- 국내 KOSPI/KOSDAQ 및 해외 NASDAQ/NYSE/AMEX 거래소 범위를 선택할 수 있다. 미선택 시 해당 시장 전체를 조회한다.
- 기준 봉의 절대 거래량 최소·최대 범위를 RVOL과 독립적으로 지정할 수 있다.
- 기준 봉 종가의 EMA20·EMA60 상/하 위치 조건을 EMA9 조건과 함께 지정할 수 있다.
- API 조회 단계의 정렬 기준(시총·RVOL·종가·거래량), 오름/내림차순, 결과 개수(1~1000)를 직접 지정할 수 있다.
- 기준 봉의 전봉 대비 등락률 최소·최대 범위를 직접 지정할 수 있다.
- 서버는 직접 조건 필드와 정렬 필드를 화이트리스트로 검증하고, OR 선택 시 EMA9 조건도 동일한 결합 규칙으로 판정한다.
- 자동화/관리자용 cron 기능은 이번 UI 비활성화 범위에 포함하지 않는다.

## 제안 UX

1. 시장: 국내·해외·전체, 해외 거래소 선택
2. 기준 봉: 일봉·주봉·월봉
3. 데이터 기준일: 최신 완료봉 또는 지정 거래일
4. 조건 그룹: 가격, 시총, RVOL·거래량, EMA, 볼린저밴드, OBV·ADL
5. 결합 방식: AND/OR와 그룹별 괄호를 명시
6. 결과 정렬: 시총·등락률·RVOL·거래대금·최신 거래일
7. 실행 상태: 진행률, 성공/실패/스킵 수, 데이터 기준일과 갱신시각 표시
8. 저장: 사용자의 개인 preset 저장/불러오기/삭제. 서버 저장 시 계정별 소유권을 강제한다.

## API 계약

기존 `POST /api/screener/run`을 단일 진입점으로 사용한다.

```json
{
  "market": "KR",
  "timeframe": "D",
  "asOf": "LATEST",
  "logic": "AND",
  "filters": [
    { "field": "D.rvol", "operator": ">=", "value": 1 },
    { "field": "D.ema9", "operator": "ABOVE", "value": true }
  ],
  "ranking": [{ "field": "D.rvol", "direction": "DESC" }],
  "limit": 100
}
```

응답에는 각 종목의 종목명·코드와 함께 사용된 봉의 거래일, DB 갱신시각, 계산된 지표, 조건별 실제값/판정 결과를 포함한다. 데이터가 부족하거나 최신 거래일이 아니면 `SKIPPED` 또는 `INSUFFICIENT_DATA`로 명시하고 조용히 후보에 포함하지 않는다.

## 서버 설계 개선

- 허용 필드·연산자·단위·범위를 서버에서 화이트리스트 검증한다.
- 모든 일반 이동평균은 EMA로 계산한다.
- 최신 거래일 판정은 시장별 거래 캘린더와 저장 봉 날짜를 비교한다.
- 스캔은 DB에서 필요한 봉만 한 번에 읽고 지표 계산은 메모리에서 수행한다.
- 요청별 `requestId`, 소요시간, 조회 행 수, 제외 사유를 기록한다.
- 기본 스크리너의 종목별 봉 조회는 EMA60·RVOL·BB 계산에 필요한 65개 봉으로 제한한다(불필요한 120개 이력 전송 방지).
- OBV·ADL 추세를 조건으로 요청하지 않은 경우 해당 시계열 계산을 생략해 CPU 사용량을 줄인다.
- 동일 조건의 짧은 시간 중복 요청은 요청 fingerprint로 병합하거나 결과 캐시를 사용한다.
- 결과 제한·타임아웃·취소를 적용해 503/504를 방지한다.
- EMA(9) 조건이 지정된 주기만 기준 주기와 함께 조회해 불필요한 일·주·월봉 전체 읽기를 방지한다.

## 단계별 개발 순서

완료:

1. preset UI 제거 및 직접 조건 안내 문구 적용
2. AND/OR, 기준일, 조건 초기화, 결과 정렬 UI 적용
3. 필터·정렬 필드 화이트리스트와 단위/범위 검증 강화
4. 지정 기준일을 API와 DB 조회에 연결
5. OR 조건의 EMA9 포함 판정 통일

후속:

1. 조건 빌더를 그룹형 UI로 개편
2. 결과 설명/실제값/제외 사유의 화면 표준화
3. 로그인 사용자 개인 preset 저장 기능 추가
4. API·UI·성능·권한 회귀 테스트 확대

## 검증 기준

- preset 버튼/호출 경로가 일반 사용자 화면에 존재하지 않는다.
- 직접 설정한 각 조건이 요청 JSON과 결과 판정에 동일하게 반영된다.
- 국내·해외 및 일·주·월봉 결과에 기준일/갱신시각 메타데이터가 존재한다.
- 잘못된 필드, 범위, 날짜, 거래소는 400으로 거부한다.
- 데이터 부족·비최신 봉은 후보로 반환하지 않는다.
