# 한솔로지스틱스 장기 배당투자 분석 설계안

## 문서 상태

- 상태: 개발 전 설계안
- 대상: 한솔로지스틱스 (KOSPI, 009180)
- 데이터 우선순위: KIS Open API 공식 데이터
- 이번 작업: 설계 문서화만 수행. 애플리케이션 코드와 DB는 변경하지 않음.
- 공식 근거: [KIS Developers API 서비스 요약](https://apiportal.koreainvestment.com/apiservice-summary), [KIS Developers](https://apiportal.koreainvestment.com/intro)

## 1. 목표와 범위

가격·거래량·재무·배당·기업행사·수급 데이터를 기준일별로 수집하고, 원천값과 파생지표를 분리해 장기 배당투자 판단 자료를 제공한다. 매수·매도 추천이나 수익 보장은 범위에 포함하지 않는다.

1차 대상은 009180이지만, 이후 국내 보통주 공통 모듈로 확장할 수 있게 설계한다.

## 2. KIS 공식 API 활용 범위

구현 직전에 KIS Developers 포털의 최신 상세 명세에서 실제 `tr_id`, 입력 필드, 출력 필드를 확인한다. 명세에 없는 값은 추정하지 않는다.

| 영역 | 확보 대상 | 활용 | 주기 |
|---|---|---|---|
| 종목정보 | 시장·코드·종목명·상품 기본정보 | 대상 검증 | 초기·정기 |
| 시세 | OHLCV·거래대금·시가총액 등 | 현재 위치·유동성 | 거래일 |
| 기간시세 | 일·주·월·년 가격 | 추세·변동성·배당락 분석 | 기간 종료 |
| 재무상태 | 자산·부채·자본 및 주요 항목 | 안정성·부채 | 공시 후 |
| 손익 | 매출·영업이익·순이익·EPS 등 | 이익과 배당 여력 | 분기·연간 |
| 재무비율 | 수익성·안정성·성장성·기타 비율 | ROE·부채·성장률 | 공시 후 |
| 배당 | 기준일·지급일·주당배당금 등 | 배당 이력·연속성 | 공시 후 |
| 기업행사 | 배당락·주총·증자·감자·합병·분할 | 이벤트 위험 | 일 1회 이상 |
| 수급 | 외국인·기관 등 제공 범위 | 보조적인 보유주체 변화 | 거래일 |
| 공매도·대차 | 제공 가능한 수급 보조 데이터 | 하락 압력·위험 | 거래일 |
| 전망·의견 | 추정실적·투자의견 등 | 참고용 기대치 | 선택 |

## 3. 분석 결과

### 배당

- 배당수익률: 최근 확정 주당배당금 / 기준일 종가
- 배당성장률: 동일 기준의 전년 대비 주당배당금 변화율
- 최근 3·5·10년 지급 연속성 및 삭감 여부
- 배당 변동성
- 이익배당성향: 주당배당금 / EPS. 기준기간이 맞을 때만 계산
- 현금흐름 배당부담: 배당 관련 현금 유출과 영업현금흐름 또는 자유현금흐름 비교

### 재무·시장

- ROE, 영업이익률, 순이익률
- 부채비율·유동성·이자부담 관련 지표
- 매출·영업이익·EPS 성장률
- 영업현금흐름과 순이익의 방향 일치 여부
- EMA 기반 추세, 프로젝트 공통 RVOL, 배당락 전후 수익률과 변동성
- 밸류에이션은 기준일과 기간을 보존해 비교

단일 종합점수만 표시하지 않고 구성요소와 결측 사유를 함께 표시한다.

## 4. 데이터 모델

기존 `instrument_fundamental_snapshots`는 현재 기본정보·시가총액·가격 스냅샷에 재사용한다. 과거 재무·배당 값은 최신값으로 덮어쓰지 않는다.

제안 논리 테이블:

- `kis_domestic_financial_periods`: 종목·기준기간·재무종류·지표코드·값·단위·원천·조회시각·payload hash
- `kis_dividend_events`: 기준일·배당락일·지급일·주당배당금·확정/예정 상태·원천·조회시각
- `kis_corporate_events`: 이벤트 종류·이벤트일·상태·설명·원천·조회시각
- `kis_investor_flow_daily`: 거래일별 투자자 분류·순매수량·순매수금액 등 제공 필드
- `kis_company_analysis_snapshots`: 기준일·분석 버전·파생지표·품질 플래그·누락 필드·원천 snapshot ID

모든 원천 데이터는 raw payload와 정규화 필드를 함께 보존하고, 동일 종목·기준일·데이터 종류는 idempotent upsert한다.

## 5. 수집 파이프라인

1. 국내 보통주 universe에서 009180을 검증한다.
2. 기존 `lib/kis.ts`와 KIS 요청 프레임워크의 토큰·재시도·잠금 정책을 사용한다.
3. 응답 상태와 필수 필드를 검증한다.
4. 원천 응답 해시와 정규화 데이터를 저장한다.
5. 기준일이 일치하는 시세·재무·배당·행사를 결합한다.
6. 분석 버전과 품질 플래그를 저장한다.
7. 조회 API는 최신 성공일·조회시각·stale 여부를 함께 반환한다.

실패 시 기존 정상 캐시를 삭제하거나 빈 값으로 덮어쓰지 않으며, Mock 데이터는 사용하지 않는다.

## 6. 모듈·갱신 방향

기존 `lib/kis.ts`, `lib/instrument-fundamentals.ts`, 금융 API 라우트와 중복되지 않게 다음 책임을 분리한다.

- KIS 인증·요청: 기존 공통 모듈
- 재무 파싱: 제안 `lib/kis-domestic-financials.ts`
- 배당·기업행사 파싱: 제안 `lib/kis-domestic-events.ts`
- 파생지표: 제안 `lib/long-term-investment-analysis.ts`
- 저장소: 원천·정규화·파생 결과별 repository

제안 파일명과 라우트는 구현 THREAD에서 현재 구조를 확인한 뒤 확정한다.

권장 주기는 일봉·현재가/거래일 종료, 주·월봉 기간 종료, 수급·행사 일 1회, 재무·배당 신규 공시 후다. 과거 백필은 rate limit·advisory lock·재시작 지점을 관리한다.

## 7. 메타데이터와 오류 처리

모든 일·주·월봉 및 분석 결과에 종목명·코드·시장·보통주 여부, 기준일/기준기간, `observedAt`, `fetchedAt`, source, raw/derived 구분, 마지막 성공일, stale 여부, 분석 버전을 포함한다.

인증 실패, rate limit, 스키마 변경, 필수 필드 누락, 기준일 불일치를 각각 구분 기록한다. 자격증명은 로그에 남기지 않고, 계산 불가 값은 0으로 대체하지 않는다.

## 8. 구현 단계와 완료 기준

3. 009180 단일 종목 smoke test 후 과거 백필
4. 장기투자 분석 API/UI 구현
5. 전체 검증 및 운영 전환

완료 기준:

- 최신 KIS 명세의 URL·`tr_id`·필드 확인
- 009180 실제 수집 성공
