# 해외 뉴스 탭 개선 기획안

## 목적과 범위

- 목적: `/market-news` 탭에서 해외 뉴스·공시 제목을 빠르게 훑고 기간·출처·종류·티커 조건으로 찾을 수 있도록 개선한다.
- 범위: 사용자 화면과 조회 API의 단계별 개선. 1차 구현은 P0의 사용자 탐색 기반과 P1의 필터/이어보기까지 포함한다. P2 개인화는 후속 범위다.
- 기준: 현재 `MarketNewsPage`, `/api/market-news`, `market_rss_articles`, 기존 `docs/architecture/us-market-rss-user-api-design.md` 설계를 확인했다.

## 현행 상태와 사용자 문제

아래 내용은 2026-10-26 1차 구현 전 기준선이다.

- 화면은 최신순 기사 목록, 동적 출처 선택, 번역 제목 우선, 원문 요약 표시로 구성된다.
- API는 최대 200건을 한 번에 읽고 `source` 문자열을 직접 필터로 받는다. 기간 선택, 페이지 탐색, 검색, 오류 재시도 UI는 없다.
- 출처 선택지는 현재 내려온 항목에서만 만들어져 특정 기간에 기사가 없는 출처를 선택할 수 없다.
- 화면은 번역 fallback/실패 상태를 표시하지 않아 원문 제목이 번역 제목처럼 보일 수 있다. 저장된 `translatedSummary`가 있어도 현재 화면은 `summary` 원문을 표시하며 “원문 요약 · 미번역”으로 고정 안내한다.
- 티커만 보이고 회사명·기사 유형·핵심 분류·콘텐츠 유무 상태는 분명하지 않다. 게시시각 미확인 외에 수집 상태/갱신시각도 사용자에게 드러나지 않는다.
- 한 번에 200건을 가져오므로 오래된 항목 탐색과 데이터 증가에 따른 응답 크기를 함께 다루기 어렵다.
- 기반 필드(원문/번역 제목·요약·본문, 번역 상태, 티커, 출처, 링크, 발행/수집 관련 시각)는 일부 이미 저장되어 있으나 화면 응답 계약은 이를 제한적으로 사용한다.

## 제품 목표

1. 사용자가 10초 안에 최신 제목을 훑는다.
2. 원문/한국어 제목 상태를 오인하지 않는다.
3. 기간, 출처, 티커, 기사 유형으로 제목 목록을 좁히고 연속해서 탐색한다.
4. 제목 외 요약·본문·메타데이터를 화면에 추가하지 않는다.
5. 모바일에서도 필터와 제목 읽기가 불편하지 않게 한다.

## 권장 정보 구조

### 1. 상단 요약 및 빠른 필터

- 제목과 결과 수: “해외 뉴스·공시”와 현재 조건에서 불러온 제목 수.
- 기간 선택: 최근 1~24시간을 1시간 단위로 선택하며 기본값은 최근 1시간이다.
- 출처 필터: 전체, SEC EDGAR, NASDAQ, NASDAQ Trader, StockTitan, GlobeNewswire. 설정된 공식 source registry를 기준으로 고정 노출한다.
- 티커 검색: 저장된 티커 문자열을 완전 일치 검색한다. 현재 저장 모델은 검증 여부를 증명할 수 없으므로 결과에 미검증 상태를 표시하고, verified-only 필터는 검증 매핑 데이터가 마련된 뒤 제공한다.
- 선택 조건은 URL query로 보존해 새로고침·공유·뒤로가기를 지원한다.

### 2. 제목 피드

- 기본 정렬은 발행시각 최신순. 발행시각이 없는 기사는 저장시각을 기준으로 조회한다.
- 기사 행에는 클릭 가능한 제목만 표시한다. 출처·티커·회사명·시각·요약·본문·상태 배지는 표시하지 않는다.
- 제목 언어 전환은 원문 제목/저장된 한국어 제목에 한정한다. 한국어 제목이 없으면 원문 제목을 보여준다.
- 제목 링크를 누르면 제공자 원문으로 이동한다.
- 결과가 많으면 커서 기반 “더 보기”를 제공하고, 스크롤 위치와 필터를 유지한다.

### 3. 상태 화면

- 로딩: 카드 자리표시자와 선택 조건 유지.
- 빈 결과: 기간/출처/티커 조건을 설명하고 필터 초기화 액션 제공.
- 네트워크/API 오류: 일반 사용자용 안내와 재시도 버튼. 내부 오류 문자열은 노출하지 않는다.
- 피드 항목 외부의 로딩·빈 결과·오류 안내만 표시한다. 출처별 갱신 시각은 사용자 피드에 표시하지 않는다.

## 우선순위 및 릴리스 제안

### P0 — 신뢰 가능한 탐색 기반

- 먼저 기존 API 사용처를 전수 확인하고, 이미 작성된 `us-market-rss-user-api-design.md`의 source allowlist·시간 범위·페이지 계약·공개 DTO 설계를 기준선으로 삼는다.
- 이 문서는 사용자 경험 우선순위와 화면 동작을 정하고, API 필드·검증·보안·페이지네이션의 상세 계약은 기존 사용자 API 설계 문서를 단일 기준으로 삼는다. 서로 다른 값이 발견되면 구현 전에 두 문서를 함께 갱신해 하나의 기준으로 맞춘다.
- source registry 및 응답 DTO를 명시해 미국 RSS 5개 출처만 화면에서 선택하도록 한다.
- 사용자 항목 API는 제목과 원문 링크만 반환한다. 요약·본문·티커·시각·출처 메타데이터와 내부 진단 데이터는 항목에서 제외한다.
- 공개 진단 route 인증 개선은 별도 보안 작업으로 추적한다.
- 로딩·빈 결과·오류·재시도 상태를 완성한다.

### P1 — 기사 발견성

- 최근 1~24시간 범위의 1시간 단위 기간 필터(기본 1시간), 정적 출처 필터, 티커 검색을 추가한다.
- 커서 페이지네이션과 “더 보기”를 도입해 최대 100건 페이지를 안정적으로 탐색한다.
- 원문/한국어 제목 전환을 제공한다. 요약·본문·메타데이터 표시 기능은 현재 범위에서 제외한다.
- 필터 상태를 URL과 동기화한다.

### P2 — 읽기 효율과 개인화

- 카드 밀도(컴팩트/상세), 읽음 표시, 즐겨찾는 티커 저장은 사용자의 실제 필요를 확인한 뒤 별도 결정한다.
- 관련 기사 묶음/중복 그룹은 정확한 canonical URL·external ID 근거와 오탐 검증 방안이 마련된 뒤 검토한다.
- 제목 요약, 본문, 기사별 부가 정보는 요청 범위에 포함하지 않으며 추가하지 않는다.

## API·데이터 설계 원칙

- 기존 설계 문서의 `hours`, allowlist `source`, `pageSize`, opaque cursor 계약을 구체 구현의 출발점으로 한다.
- 시간 필터와 정렬은 DB의 게시시각을 사용하되, 카드/사용자 DTO에는 시각 필드를 노출하지 않는다.
- 티커 검색은 저장된 `detectedTicker`에 완전 일치 적용하되 카드에는 티커 값을 노출하지 않는다.
- 사용자 피드는 DB에 저장된 제목만 읽으며 외부 크롤링·자동 번역을 하지 않는다.
- 피드 API는 목록에 필요한 제목·링크만 select해 응답 크기를 제한한다. 실제 쿼리 계획을 확인한 뒤 정렬 인덱스를 제안한다.
- 기존 `/api/disclosures` 국내·통합 조회 계약은 이 기획의 변경 범위에서 제외한다.

## 성공 지표

- 관찰 이벤트(집계 가능·개인정보 최소화): 필터 사용률, 원문 열기율, 기간별 기사 탐색 깊이, 검색 후 결과 없음 비율.
- 품질 지표: 원문/한국어 제목 전환 사용률, 필터 사용률.
- 성능 지표: API p95 응답시간, 페이지당 payload 크기, 첫 카드 표시시간.
- 초기 2주 기준값을 기록한 뒤 개선 목표를 정한다. 데이터 없는 상태에서 임의 목표 수치를 만들지 않는다.

## 검증 및 완료 조건

- API: 허용 출처/기간/페이지 크기 검증, cursor 경계 중복·누락 없음, 항목에 제목·링크 외 기사 정보가 없는지 확인, 장애 응답 마스킹.
- UI: 제목만 표시되는지, 원문/한국어 제목 전환, 빈 데이터/오류/재시도, 모바일 레이아웃, URL 조건 복원 확인.
- 회귀: `/api/disclosures` 및 관리자 RSS 파이프라인의 기존 계약이 유지됨을 확인.
- 운영: 배포 후 실제 사용자 API의 source 범위·페이지 경계·제목 전용 항목 응답을 표본 점검.
- 코드 구현 시 저장소의 `AGENTS.md`에 따라 빌드·테스트·실행 검증 및 근본 원인/재발 감지 기록을 남긴다. 테스트 추가/실행은 사용자가 요청한 경우 진행한다.

## 구현 진행 상태 (2026-10-26)

- **반영**: 1~24시간(1시간 단위, 기본 1시간), 고정 미국 출처 선택, 뉴스/SEC 공시 필터, 티커 입력, URL query/hash 보존, 원문/한국어 제목 전환, 기본 50건 및 커서 기반 더 보기, 로딩/빈 결과/오류/재시도 화면. 필터 변경 시 이전 요청을 취소해 오래된 응답이 새 결과를 덮지 않게 한다.
- **API 반영**: 허용 출처·시간 범위·페이지 크기·티커 형식 검증, 게시시각 기준 시간창(게시시각이 없으면 최초 저장시각), 안정 정렬, 기사 항목은 제목/원문 링크만 반환한다.
- **범위 제한**: 카드에 제목만 표시한다. 출처·유형·티커 필터와 제목 원문/한국어 전환은 유지한다. 요약·본문 표시 및 번역을 추가하지 않는다.
- **검증 상태**: `docs:check`와 `git diff --check` 통과. 전체 프로젝트 typecheck는 기존 `scripts/analyze-kr-industry-turnover-kis.ts` 오류로 실패했으며 해외뉴스 API/UI 관련 오류는 출력되지 않았다. 전체 테스트, build, 실제 사용자 endpoint 응답 검증은 수행하지 않았다.
- 이 항목은 구현 진행 기록이며, 전체 완료 조건(자동 테스트와 실제 endpoint 확인)을 충족했다는 뜻은 아니다.

## 후속 검토

- 읽음/즐겨찾기 같은 개인화는 별도 요청이 있을 때 검토한다.
- 제목 외 정보(요약·본문·출처/티커/시각 메타데이터)는 현재 요청 범위에 포함하지 않으며 피드 UI/API 항목에 추가하지 않는다.
