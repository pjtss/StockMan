# 기능 인벤토리 및 제품 평가

## 제품 판단

StockMan은 이미 수집·캐시·탐지·알림·관리자 디버깅까지 갖춘 운영형 시스템이다. 현재 병목은 지표 부족이 아니라 데이터 최신성, 공통 필터 일관성, 중복 알림, 실패 원인 가시성이다. 따라서 신규 지표보다 아래 운영 기준을 우선한다.

| 영역 | 현재 평가 | 우선 개선 방향 |
|---|---:|---|
| 데이터 수집 | 높음 | 원본 시각·fallback·재시도 결과 표준화 |
| 캐시/DB | 높음 | 실행 이력 축약 저장·보존 정책·인덱스 점검 |
| 탐지 신호 | 높음 | 공통 적격성 필터와 통합 점수 일관성 |
| 알림 | 중간 | 동일 종목 중복 제거·실패 재전송·완료 요약 |
| 관리자 UX | 중간 이상 | 모달 중심 원본 조회·실행/알림 상태 결합 |
| 운영 자동화 | 중간 이상 | cron 커버리지·품질 게이트·장애 격리 |

## 기능 분류

| 기능군 | 주요 모듈 | 기준 데이터 | 결과 |
|---|---|---|---|
| 시장/공시 수집 | SEC EDGAR, DART, Market RSS | 공식 피드·원문 | 저장·분류·Discord |
| 시장 캐시 | 국내/해외 일봉, 당일 시가, 유통주, 상품분류 | KIS 및 fallback 출처 | PostgreSQL 캐시 |
| 일봉 신호 | OBV, ADL, MACD, DMI, MFI, 돌파 | 저장된 일봉 | 후보·통합 점수 |
| 밴드/가격 | 국내·해외 일봉/1분봉 볼린저, VWAP | 저장 캔들·당일 시세 | 조건 충족 종목 |
| 수급/거래 | 거래대금, turnover, 체결강도, short borrow | KIS·FINRA·Alpaca 등 | 후보·점수·알림 |
| 운영 도구 | 관리자 테스트, health, observability | 실행 이력·원본 응답 | 진단·설정 |

## 공통 완료 조건

새 기능은 기능별 API만 추가하는 것으로 완료하지 않는다. 다음을 함께 제공해야 한다.

1. `FEATURE_MODULES` 등록과 관리자 설정 경로
2. 공통 적격성 필터 및 데이터 최신성 정책
3. `automation_runs` 실행·실패·스킵 기록
4. 원본 응답 또는 원본 보존 위치
5. Discord 전송·중복·재시도 정책
6. 관리자 테스트와 원본 JSON 확인
7. 단위 테스트·`npm run verify` 통과

## 다음 우선순위

### P0: 운영 신뢰성

- 캐시 자동화의 마지막 성공 시각과 실제 데이터 기준일을 함께 표시
- 실패·재시도·fallback 통계를 관리자와 Discord 요약에 통일
- `automation_runs` 보존 기간과 정리 작업을 명시

### P1: 탐지 품질

- 모든 일봉 탐지의 공통 상품 제외·가격·유동성 필터 통합
- 통합 점수의 신호별 근거와 데이터 부족 사유 표시
- 동일 종목/동일 기준일 중복 알림 방지

### P2: 운영 편의

- 기능 설정·최근 실행·알림 상태를 한 화면에서 연결
- 원본 응답 복사와 요약 JSON 복사를 공통 컴포넌트로 통일
- 수동 테스트와 실제 COMMIT 자동화 경계를 명확히 표시

이 문서는 매 기능 추가 시 갱신하며, 구현되지 않은 기능을 현재 제공 기능으로 표시하지 않는다.
