# 대화 단축어

이 문서는 사용자가 대화에서 단축어를 입력했을 때 수행할 기준과 응답 형식을 관리한다. 조회 단축어는 운영 서버의 read-only 데이터 조회만 수행한다. 캐시 동기화 단축어는 운영 공개 API에서 데이터를 읽어 로컬 DB에 저장하며, 운영 DB에는 직접 접속하거나 쓰지 않는다.

## 공통 처리 기준

- "최신 3거래일"은 조회 시점 기준 각 시장에서 가장 최근 완료된 정규장 거래일 3개를 뜻한다. 달력상 휴장일은 세지 않으며, 거래일은 결과 작성 전에 운영 서버 데이터에서 확인한다.
- 등락률 조건은 최신 3거래일 각각의 종가를 그 직전 거래일 종가와 비교해 계산한다: `(해당 거래일 종가 / 직전 거래일 종가 - 1) × 100`. 단축어의 상승률 기준은 최신 3거래일 중 하루라도 충족하면 통과한다. 장중 현재가나 KIS 상승률 TOP 100을 일봉 종가 수익률 대신 쓰지 않는다.
- 운영 서버의 활성 공식 종목 마스터에서 `COMMON_STOCK`으로 확인된 종목만 포함한다. 분류·활성 상태·일봉·시총 또는 통화 확인이 안 되면 fail-closed로 제외한다. ETF, ETN/ETP, 펀드, 워런트, 권리, 유닛, 우선주, DR, 레버리지/인버스 등 비보통주는 제외한다.
- 시총은 전날 완료 일봉의 종가 × 운영 fundamentals의 최신 상장주수로 산출한 거래일 기준 근사치로 판정한다. 해당 시장 통화(미국 USD, 국내 KRW)와 유효한 양수 종가·상장주수·관측시각을 확인할 수 없으면 제외한다. fundamentals의 `marketCap` snapshot은 교차 확인용으로 보존하되 전날 종가와 날짜가 다르면 시총 경계 판정에 그대로 쓰지 않는다. 조회 시 거래일, 일봉 갱신시각, 주식수 관측시각과 데이터 누락 여부를 내부적으로 점검한다.
- 정상 응답은 종목명이나 등락률 없이 티커만 대문자로 출력하고 쉼표(`,`)로 구분한다. 결과가 없으면 `해당 조건 종목 없음`, 운영 데이터 조회가 실패하거나 기준 거래일을 확인할 수 없으면 `운영 서버 조회 실패`라고 응답한다. 조회 실패를 빈 결과로 바꾸지 않는다.

## 문서와 실행 경계

- 이 목록은 Codex 대화에서 사용하는 조회 별칭의 정의다. 별칭 자체를 웹/API 라우트나 예약 작업으로 노출하지 않는다.
- `ㄷㅊㅇ3`·`ㄷㅊㅇ4`는 로컬 동기화 작업을 시작하는 별칭이다. 실행 전 `.env.local`의 `LOCAL_DATABASE_URL`이 의도한 로컬 DB를 가리키고 `DAILY_CACHE_API_URL`이 운영 서버를 가리키는지 확인한다. 실행은 `npm run sync:daily-cache -- --market=US --timeframe=D` 또는 `npm run sync:daily-cache -- --market=KR --timeframe=D`를 사용한다. 이 명령은 로컬 캐시를 upsert하고 일봉 요약을 갱신하며, 기본 설정에서는 운영 fundamentals API 결과도 로컬 snapshot에 반영한다. 운영 DB에 쓰지 않는다.
- `ㄷㅊㅇ5`·`ㄷㅊㅇ6`은 `.env.local`의 `DAILY_CACHE_API_URL` 운영 서버에서 공식 활성 보통주 목록을 페이지 조회하고, 그 목록을 기준으로 거래소별 100종목 이하 일봉 요청을 보낸다. 미국 KIS 마스터는 `isdr`만으로 DR 여부를 확정하지 않고 영문 상품 설명에 ADR/ADS/depositary/depository security가 명시된 항목도 제외해야 한다. 받은 전체 응답을 검증한 뒤에만 추적 대상 JSON 파일 하나를 교체한다. API 오류, 응답 envelope 오류, 마스터와 응답의 종목명 불일치, 거래소·코드 중복, 일봉 품질 오류가 하나라도 있으면 기존 JSON 파일을 보존하고 작업을 실패 처리한다. 운영 응답에 봉이 없는 활성 종목은 별도 누락 배열에 남긴다. 결과에는 대상 수, 응답 수, 누락 수, 조회 UTC 시각, 거래소별 최신 일봉 기준일, 종목별 일봉 거래일과 fetchedAt을 기록한다. 조회는 운영 DB에 쓰지 않는다.
- 완료 응답은 실행 결과의 대상·수신·저장·누락 수를 구분한다. API 오류, 응답 유효성 오류 또는 DB transaction 실패는 성공/완료로 보고하지 않는다. 봉 누락과 fundamentals 미보유는 별도 수치·코드 표본으로 안내한다.
- 기존 상승률 TOP 100 API는 장중/최근 수집 순위 응답이므로 이 단축어의 최신 3거래일 종가 기준 전체 유니버스 스크린으로 간주하지 않는다.
- 운영 read-only API가 최신 3거래일과 각 비교용 직전 거래일의 완료 일봉 및 fundamentals를 충분히 제공하지 않으면 조건을 추정하거나 로컬 캐시로 대체하지 말고, 누락 원인과 기준일을 보고한다.
- 외부 읽기 API 경로를 새로 구현하는 경우 공개 GET 정책, OpenAPI 및 route inventory 규칙을 별도 적용한다.
