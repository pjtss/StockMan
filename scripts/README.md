# 운영·개발 스크립트

- 관리자 화면 `/admin/modules/instrument-universe`에서 **국내 KIS 종목 마스터만 적재**를 제공한다. `kospi_code.mst`와 `kosdaq_code.mst` 공식 파일 두 개만 받으며, 미국 유니버스에는 쓰지 않고 기존에 누락된 종목도 비활성화하지 않는다. 운영 국내 유니버스가 비어 있을 때 이 경로로 대상 목록을 준비한다.
- 같은 화면의 **전체 국내 보통주 표준산업분류 코드 갱신**은 운영 API가 관리하는 활성 `COMMON_STOCK` 목록을 기준으로 KIS 주식기본조회(`CTPF1002R`, `/uapi/domestic-stock/v1/quotations/search-stock-info`)를 종목별 호출하고 `std_idst_clsf_cd`/`std_idst_clsf_cd_name`을 10종목 단위 트랜잭션으로 저장한다. 전체 대상 수 변경, KIS 응답 오류, 코드/표준코드 검증 실패 시 해당 묶음은 저장하지 않는다. 두 경로 모두 관리자 세션이 필요하다. 진행상태 GET은 관리자 세션 또는 `DAILY_CACHE_READ_API_KEY`를 사용한다.

- `local-rss-bullish-report.mjs`: `--prepare`는 운영 RSS API를 GET해 임시 JSON을 만든다. Codex가 `--input <JSON> --batch-offset <0-based>`로 8개씩 읽어 직접 분석하고, `--record-results-base64`로 결과를 임시 JSON에 누적한 뒤 `--analysis <JSON>`로 렌더하면 HTML을 Downloads에 저장한다. POSITIVE이며 명확한 ticker symbol인 카드만 수록한다. API key/외부 LLM 호출은 없다. 기존 HTML은 `--filter-existing-positive-known-ticker --date YYYY-MM-DD`로 로컬 필터링할 수 있다. `npm.cmd run report:rss-bullish -- --help`로 사용법을 확인한다.
- `local-rss-llm-agent.mjs`: Codex 매분 예약 회차가 `--prepare [limit]`으로 신규 RSS revision을 가져와 직접 분석하고, 구조화 JSON을 PowerShell stdin pipe로 `--save-stdin`에 전달해 운영 DB에 기록한다 (`--save-base64`도 지원). `--deliver`는 승인된 전용 Discord URL로 PENDING만 claim 후 한 번 전달하며 timeout은 자동 재전송하지 않는다. `--status`는 저장된 전송 상태를 조회한다. 서버 V141 migration/API/token과 로컬 token/webhook 설정이 먼저 필요하며 Codex 예약 작업이 모델 분석을 맡는다.
- `lib/local-rss-watch/feed-source.mjs`: 모듈 1. StockTitan·SEC EDGAR 원본 호스트 제한, HTTPS GET, SEC User-Agent, 응답 타입/크기/timeout 검사, 공통 RSS/Atom 파싱을 맡는다. `feed-source.test.ts`에서 두 포맷과 거절 조건을 고정 검증한다.
- `lib/local-rss-watch/local-store.mjs`: 모듈 2. 출처별 최초 기준점, GUID/링크 기반 중복 제거, 최대 10,000개 ID 상태 JSON, UTF-8 안전 CSV 대기열/분석 결과 기록을 맡는다.
- `lib/local-rss-watch/analysis-contract.mjs`: 모듈 3. RSS를 자동 판정하지 않고 Codex가 작성한 판정/근거/위험/신뢰도/ticker 결과의 스키마만 검증한다.
- `lib/local-rss-watch/file-lock.mjs`: 모듈 5. watcher와 heartbeat CLI 사이 CSV/state 파일 읽기-수정-쓰기 경합을 막고, owner process가 종료된 stale lock만 회수한다.
- `lib/local-rss-watch/analysis-inbox.mjs`: 모듈 6. Codex 실행기가 분석 JSON을 프로젝트의 gitignore된 전달함에 기록하고, Downloads 쓰기 권한을 가진 watcher가 CSV에 적용한다. `--record-id`는 최대 15초간 소비 여부를 기다려 `applied`를 반환하며, timeout/실패 파일은 전달함에 남아 재시도된다.
- `lib/local-rss-watch/retry-policy.mjs`: 모듈 7. 원본 HTTP 429의 `Retry-After`를 source별 cooldown으로 바꿔 과도 재요청을 줄이며 다른 피드 및 inbox 처리는 멈추지 않는다.
- `local-rss-poller.mjs`: `npm run rss:watch`가 원본 어댑터와 저장소 모듈을 10초 주기로 orchestration한다. 운영 서버/API/DB와 Discord는 사용하지 않는다. `--pending 10`은 CSV read-only 조회, `--record-id <item_id> --result-base64 <UTF-8 JSON base64>`는 workspace inbox 큐잉이다. Downloads CSV 실제 반영은 다음 watcher cycle이 맡는다. `--backfill-current`는 현재 원본 feed 항목을 `INITIAL_BACKFILL`로 중복 없이 초기 분석 queue에 넣는 명시적 one-shot이다.

- `dev-server.mjs`: 로컬 개발 서버 실행
- `local-env.mjs`: `.env.local` 파싱과 주입의 단일 기준. 로컬 실행·DB 도구에서는 파일 값을 상위 셸보다 우선하며 값은 출력하지 않는다. 개별 스크립트에서 파서를 다시 구현하지 않는다. `load-local-env.mjs`는 기존 `node --import` 연구 스크립트를 위한 호환 preload다.
- `clean-next.mjs`: 지정한 Next.js 산출물 정리. `predev`는 `.next-dev`만 정리하며 production `.next`는 건드리지 않는다.
- `sync-daily-cache-async.mjs`: 운영 API의 일봉을 로컬 PostgreSQL에 동기화한다. `--date=YYYY-MM-DD`는 지정 거래일 봉만 저장한다. 국내 시총 1조 미만 보통주만 갱신할 때 `node --import ./scripts/load-local-env.mjs scripts/sync-daily-cache-async.mjs --market=KR --timeframe=D --market-cap-under=1000000000000`을 사용한다. 국내 기본 시총 하한 300억 원을 적용하려면 `--market-cap-over=30000000000`을 함께 지정한다. `--market=US --timeframe=D --us-market-cap-under=100000000`은 로컬 `instrument_fundamental_snapshots`의 USD 시총 스냅샷이 양수이고 1억 달러 미만인 활성 `COMMON_STOCK`만 대상으로 하며, 통화·시총 미확인 종목은 제외한다. 국내 시총 조건은 운영 fundamentals API의 KRW 스냅샷만 통과시킨다.
- `refresh-us-smallcap-fundamentals.ts`: 기본 시총 상한은 5억 달러이며 `--max-market-cap-usd=<USD>`로 변경할 수 있다. 상한 이하의 활성 미국 COMMON_STOCK 중 시총 캐시가 없거나 USD 시총 캐시가 1일 이상 지난 종목만 조회해 로컬 `instrument_fundamental_snapshots`를 갱신한다. 기본 전체 모드는 KIS price-detail을 호출한다. `--codes=AAA,BBB` 지정 모드는 `.env.local`의 read-only 운영 API를 GET해 출처가 `KIS_OVERSEAS_PRICE`이고 USD·양수 가격·양수 시총·시총 상한·관측/수집시각이 확인된 최신 스냅샷만 로컬에 반영한다. 로컬 DB에 현재 존재하지 않는 shares 컬럼에 의존하지 않으며 history 테이블은 쓰지 않는다. 미확인 시총은 조회 대상에 포함하고, 비-USD로 확인된 기존 스냅샷은 제외한다. 기본은 preview이며 실제 호출은 preview의 건수와 SHA-256을 `--apply --expect-count=<count> --expect-fingerprint=<sha256>`에 전달해야 한다. 로컬 DB host만 허용한다.
- `oci-cron.sh`: OCI 예약 HTTP 호출과 실행 요약
- `register-discord-commands.mjs`: Discord Slash Command 등록
- `check-docs.mjs`: 문서 진입점·migration 파일명 검증
- `retry-failed-instrument-fundamentals.ts <ISO-since> --preview`: 지정한 시각 이후 로컬 스냅샷이 갱신되지 않은 활성 종목과 해당 scope SHA-256을 출력하며 KIS 호출은 하지 않는다. `--apply <expected-count> <expected-scope-sha256>`은 preview의 건수와 지문을 명시한 경우에만 실행한다. 건수만 같고 종목 구성이 달라지면 KIS 호출 전에 중단한다. 반드시 `scripts/dev-server.mjs`와 같은 `.env.local` 우선 규칙을 적용하고, 운영 DB에서는 실행하지 않는다.
- `refresh-all-instrument-fundamentals.ts`: 기본 실행은 로컬 활성 종목 수, 시장별 범위와 정렬된 정확한 `market/code` 집합의 SHA-256 `scopeFingerprint`를 미리 본다. 실제 전체 KIS 호출·DB 저장은 preview의 `--apply --expect-total=<확인한 활성 종목 수> --expect-total-fingerprint=<확인한 scopeFingerprint>`를 모두 줘야 하며, 두 값 검증 후에도 preview에서 지문을 만든 동일한 instrument 목록을 refresh 함수에 전달해 조회 사이 universe 변경으로 scope가 바뀌지 않게 한다. DB hostname이 localhost가 아니면 거부한다. 실행 중 진행 로그에는 wall elapsed, 동시 KIS fetch 호출시간 합계, DB transaction 시간 합계, writer 시작 전 쓰기 큐 대기시간 합계(큐 포화 backpressure 포함)가 포함되며, 최종 결과에는 처리율과 시장별 fetch 시간도 포함된다. 결과 카운터는 `instrumentCount = completeCount + failedInstrumentCount`로 종목 단위 합계를 보장한다. `persistedCount`는 부분 데이터 행을 포함해 실제 DB에 저장된 종목 행 수이고, `successCount`는 필수 검증까지 통과한 완전 성공 종목 수다. `failureCount`와 `failureSummary`는 종목 수가 아니라 실패 이벤트/사유 건수라 한 종목에 복수 원인이 있으면 `failedInstrumentCount`보다 클 수 있다. 실패 결과에는 모든 실패 건을 집계하는 원문 응답·티커 비노출 `failureSummary`와 별도로 최대 100건의 상세 샘플이 포함된다. 동시 호출의 구간별 시간은 겹치므로 합계가 wall time과 같지 않다. 가격이 유효하고 시총만 NULL/0 이하인 경우도 가격·거래대금 등 다른 quote 필드는 history와 snapshot에 저장하며, 시총은 history와 snapshot 모두 최신 KIS 값이 없으면 NULL로 저장해 오래된 값을 최신값처럼 노출하지 않는다. verifier는 snapshot의 시총이 최신 history와 다르면 `snapshot_market_cap_mismatch_rows`로 실패 처리한다. 실행 후 별도의 `--verify-since=<ISO시각>` 옵션으로 해당 시각 이후 활성 전체의 이력 존재, 필수값 NULL, 양수 가격 및 시가총액, 해외 `trading_value`와 KIS 원문(JSON의 `output`/`output1`/`output2`, `tamt`/`tamnt` 우선, 없거나 0이면 `pamt`) 일치 여부를 확인한다. KIS 원문에서 양쪽 거래대금이 모두 0인 경우 저장 0을 유효하게 허용하되, NULL 또는 원문과 다른 값은 통과시키지 않는다. 한 종목이라도 누락·비정상 시총·가격 오류·원천값 불일치·최신 스냅샷 불일치가 있으면 JSON 요약에 `ok:false`를 표시하고 종료 코드 1을 반환한다. `.env.local`이 상위 셸보다 우선하며 자격증명은 출력하지 않는다.
- `instrument-fundamental-refresh-repository.ts`: 전체 갱신 CLI의 활성 유니버스, 누락 종목, 데이터 품질 실패 대상과 사후 검증 SQL을 한 모듈에서 제공한다. CLI와 Vitest mock 테스트가 같은 query 경계를 사용하며, 실제 로컬 전체 갱신·verifier 호출은 `.env.local`의 localhost DB만 대상으로 한다.
- `refresh-all-instrument-fundamentals.ts --retry-invalid-since=<ISO시각>`: 해당 구간의 가장 최신 갱신행을 활성 종목과 대조해 누락 이력, 비양수 가격/시총, NULL 거래대금, 해외 KIS 거래대금 원문 불일치만 재조회 대상으로 선정한다. 기본은 preview이며 출력된 `scopeFingerprint`까지 복사해 `--apply --expect-invalid=<preview 건수> --expect-invalid-fingerprint=<preview 지문>`을 모두 맞춰야 호출한다. `--retry-missing-since=<ISO시각>`도 preview에서 scope fingerprint를 출력하며 apply 때 `--expect-missing`과 `--expect-missing-fingerprint`를 모두 확인한다. 세 모드 모두 같은 건수의 다른 종목 구성으로 KIS 호출이 진행되지 않는다. 검증 모드와 retry 모드를 동시에 선택할 수 없다. 검증 집계도 구간별 재시도 history 전체 행이 아니라 종목별 최신 history 한 건만 대상으로 하여 결측 건수를 종목 수 기준으로 표시한다. 운영 DB 접근은 계속 금지된다.
- Refresh CLI 옵션은 `instrument-fundamental-refresh-cli`에서 DB/env 초기화 전에 검증한다. 확인 건수는 양의 안전 정수, fingerprint는 64자리 SHA-256이어야 하며, 각 모드에서 허용하지 않는 옵션·중복 옵션·미지정 인수·모드 혼합은 KIS/DB 호출 전에 거부한다.
- 검증의 `snapshot_market_cap_mismatch_rows`는 최신 history와 snapshot 시총의 불일치 수를 표시한다. 새 upsert 정책은 KIS 시총이 결측이면 snapshot도 NULL로 갱신하며, 과거 불일치 데이터가 남아 있으면 완료 판정을 통과하지 못한다.
- `--verify-since=<ISO시각>`의 품질 카운트와 `invalidMarketCapSamples`는 재시도 이력의 모든 행을 누적하지 않고 활성 종목별 최신 history 한 건으로 집계한다. 따라서 보고되는 결측 건수는 history row 수가 아니라 종목 수이며, retry 직후에도 최종 상태를 반영한다.
- `audit-flyway-history.ts`: `.env.local`의 localhost DB에서만 Flyway 성공 이력과 저장소 migration 파일 버전을 읽어 비교하고 V85/V89의 원본·캔들·대상 relation 구조 전제조건을 조회 전용으로 출력한다. 대상 relation 행 수는 추정치이며 사전조건 통과도 migration 안전 승인이 아니다. V85/V89는 데이터 삭제/rename을 수행한다. 미적용/실패 migration이 있으면 비정상 종료코드로 보고하며 checksum 확인, migration 실행·이력 수정은 하지 않는다.
- `verify-sec-company-facts-local.ts [CIK]`: `.env.local`의 localhost DB와 비-placeholder `SEC_USER_AGENT` 및 공식 `data.sec.gov` host를 확인한 후 단일 CIK Company Facts를 실제로 수집·저장한다. `sec_source_snapshots` 원문 JSON과 `sec_xbrl_snapshots.payload` 전체 구조·필드의 deep equality 및 원문 SHA-256을 DB에서 재조회해 검증한다. 기본 CIK는 Apple (`0000320193`)이며, 운영 DB에는 쓰지 않는다. SEC User-Agent 조건이 충족되지 않으면 요청 전에 중단한다.
- `sec-company-facts` 운영 자동화: OCI `oci-cron.sh`가 `/api/cron/sec-company-facts`를 호출한다. 전용 관리자 모듈의 KST 실행시간(기본 매일 08:00)을 적용하고 PostgreSQL advisory lock 및 KST 날짜별 성공 이력을 사용한다. 예약·수동 수집 모두 SEC 티커 매핑 후 활성 `COMMON_STOCK`가 해외 종목 마스터에서 확인된 경우에만 SEC Company Facts를 호출한다. `/other`의 관리자 UI는 티커/CIK 단건 수집과 저장 JSON 조회를 제공한다.
- 전체 fundamentals 갱신 검증은 해외 `trading_value`가 원본 KIS `tamt`/`pamt`와 일치하는지와, 갱신 이력의 최신 스냅샷이 누락·지연되거나 같은 적재시각의 가격/거래대금/시총이 다른지도 검사한다. 이력과 스냅샷 저장은 같은 DB transaction으로 기록하며, 이 게이트는 사후 확인이다.
- `reconcile-us-universe.ts`: 로컬 해외 common/special universe를 현재 `classifyUs` 기준으로 dry-run 진단한다. 실제 이동은 `--apply`와 두 방향의 예상 건수를 모두 전달해야 하며, `.env.local`의 localhost DB만 허용한다. 이동·출처 비활성화는 단일 DB 트랜잭션에서 수행하고 사후 dry-run이 0건인지 확인한다.
- `market-rss-translation-review-import.mjs`: 관리자 RSS 번역 검수 CSV를 기본 미리보기로 검증하고, `--apply`가 있을 때만 `lib/fixtures/market-rss-translation-review.json`에 사람 검수 품질 fixture를 병합한다. export의 외부 기사 ID를 기준으로 stable identity를 만들며, 원문 요약은 검수 참고 근거로 fixture에 보존한다. 운영 번역 경로는 제목만 provider에 보내며, fixture의 원문 요약은 사람 검수 참고 자료로만 보존한다. 기대 번역은 원문의 수치·티커 보호 토큰 값과 반복 횟수를 그대로 보존해야 하며 원문에 없는 숫자/티커는 거부한다. `RSS-ID:`, `RSS-TICKER:`, `RSS-TIME:` 접두어는 원 값으로 복구한다. 이전 두 CSV 형식과 legacy fixture도 가져와 점진 승격한다. production 번역기와 공유하는 보호 토큰 보존, non-accurate 수정안, CSV 형식, URL/날짜, 수식 prefix를 확인하며 `보류` 행은 fixture에서 제외한다. 외부 API/DB를 호출하지 않는다.
- `check-market-rss-translation-coverage.mjs`: 사람 검수 semantic fixture가 1건 이상인지 확인하고, fixture가 비어 있으면 종료 코드 1로 실패한다. 이 검사는 명시적으로 실행하는 별도 점검이며 현재 `npm run verify`와 `npm run deploy:verify`에는 연결되어 있지 않다. fixture가 비어 있으면 검사 명령은 실패하고 semantic regression suite는 skip되므로, 현재 배포 검증은 provider의 의미 정확성 coverage를 증명하지 않는다. 로컬 일반 `npm test`는 fixture 미수집 동안에도 실행할 수 있다.

번역 검수 반영 예시:

```powershell
node scripts/market-rss-translation-review-import.mjs --input .\Downloads\rss-translation-review-stocktitan-2026-09-25.csv
node scripts/market-rss-translation-review-import.mjs --input .\Downloads\rss-translation-review-stocktitan-2026-09-25.csv --apply
npm.cmd exec vitest run -- lib/market-rss-translation-review-fixtures.test.ts
```

첫 명령은 현재 fixture를 읽어 병합 결과를 미리 보여주되 파일은 변경하지 않는다. 따라서 이미 반영된 행은 중복으로 표시하고 기존 케이스와 내용이 다르면 미리보기 단계에서 충돌로 거부한다. 입력 CSV와 판정을 직접 확인한 뒤에만 `--apply`를 사용한다. `--apply`는 같은 디렉터리의 고유 임시 파일을 쓴 뒤 rename하며, rename 실패 시 임시 파일을 지우고 기존 fixture를 보존한다.

운영 스크립트는 비밀값을 출력하지 않고, 실패 시 원인과 기능별 요약을 남겨야 합니다.

스크립트가 제품 런타임의 도메인 규칙을 복제하지 않도록 운영 진입점과 자동화 책임은 [`../docs/architecture/system-module-catalog.md`](../docs/architecture/system-module-catalog.md)의 자동화·운영 경계를 기준으로 합니다.
